# act Configuration

This repository includes [`.actrc.example`](../../../.actrc.example) as a reusable starting point for local [nektos/act](https://github.com/nektos/act) runs.

## Setup

Copy the example into the workspace root where you run `act`:

```sh
cp .actrc.example .actrc
```

A typical workspace can look like this:

```text
my-project/
├── .actrc
└── my-repository/
    ├── .github/
    │   └── workflows/
    │       └── pipeline-local.yaml
    └── .secrets
```

Run `act` from the workspace root and point it at the repository workflow and secrets file:

```sh
cd ~/my-project

act push \
  -W my-repository/.github/workflows/pipeline-local.yaml \
  --secret-file my-repository/.secrets
```

## Parsing rules

`.actrc` is not a shell script. `act` parses its configuration by splitting values on whitespace, so shell-style quoting should not be relied on.

Prefer:

```text
--flag=value
```

Avoid:

```text
--flag="value with spaces"
```

## Example defaults

The provided example config:

- reuses a locally available runner image instead of pulling it before every run;
- maps `ubuntu-latest` to `catthehacker/ubuntu:act-latest`;
- attaches workflow containers to `platform_net`;
- runs containers as `linux/amd64`;
- allows up to four jobs to run concurrently;
- stores local workflow artifacts in `/tmp/artifacts`;
- leaves `--reuse` disabled because stale or externally removed containers can make reuse unreliable.

Customize these values for your local environment before treating the file as a project default.

## Docker networking

When workflow containers are attached to a Docker network, reach other containers by Docker service name, for example:

```text
http://sonarqube:9000
https://portainer:9443
```

Inside a workflow container, `localhost` refers to that container itself rather than another service on the Docker network.

## Container cleanup

If local `act` containers become stale, remove them with:

```sh
docker rm -f $(docker ps -aq --filter "name=act-")
```

Only run cleanup when you intend to remove all containers matching the `act-` name filter.

## Secrets

Keep secrets outside the example config. Pass them separately with `--secret-file` or another supported `act` mechanism.

Do not commit real `.secrets` files.


## Troubleshooting: workflow file not found

An error such as:

```text
Error: stat /path/to/console/.github/workflows/reusable_select-recovery-packages.yml: no such file or directory
```

means `act` cannot open the workflow file selected for execution. It is **not** a Docker socket or container architecture failure.

1. Check the workflow files actually present in the selected repository:

   ```sh
   cd /path/to/console
   ls .github/workflows/
   ```

2. Run the **calling** workflow that exists in this repository, not the filename of a remote reusable workflow. For example, if `release.yml` calls a shared workflow:

   ```yaml
   jobs:
     select-packages:
       uses: moyarich/reusable-workflows/.github/workflows/reusable_select-recovery-packages.yml@main
   ```

   run the caller using:

   ```sh
   act workflow_dispatch -W .github/workflows/release.yml
   ```

   Replace `release.yml` and the event with the actual caller filename and trigger. In the VS Code extension, select that same existing caller workflow before running an individual job.

3. If the caller uses a **local** reusable workflow reference such as `./.github/workflows/build.yml`, verify that the file exists in the caller repository. A remote `owner/repo/.github/workflows/file.yml@ref` reference should not be copied into the caller repository just to satisfy a local existence check.

4. If the caller file exists but `act` cannot load its remote reusable dependency, inspect the actual `act` error, verify the upstream repository/ref/file and access permissions, and check `act --version`. Runner support for some GitHub Actions workflow features may vary. Fixing a bad `-W` path does not by itself guarantee that a remote workflow will execute.

### Apple Silicon warning

On Apple M-series Macs, `act` may print a warning suggesting `--container-architecture linux/amd64`. This warning is separate from a missing workflow file.

To run containers as AMD64, add this line to the `.actrc` loaded by `act`:

```text
--container-architecture linux/amd64
```

Or use `act --container-architecture linux/amd64 workflow_dispatch -W .github/workflows/release.yml`.

AMD64 emulation may be slower than native ARM64. Choose the architecture expected by the workflow's container images and dependencies; it is not necessary to force AMD64 solely to resolve a workflow path.

When using the VS Code extension, ensure the setting is in a configuration location `act` actually reads for the selected working directory. The extension invokes `act` from the selected repository by default. If the architecture warning remains, test the equivalent command directly from that directory to determine which `.actrc` is loaded.

### About `act exited with code 1`

The extension may display `act exited with code 1` after the underlying `stat` error. This is the process exit status, not a second root cause. Address the first concrete error in the `act` output.
